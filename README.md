# Castro Finish Carpentry — website

Static site for **Castro Finish Carpentry Inc** (castrocarpentryinc.com), finish carpentry and exterior repairs on Cape Cod, MA.
Plain HTML/CSS/JS generated by one Python script. Hosted on **Hostinger** (Apache/LiteSpeed), replacing the old WordPress site.

## How it works

Everything is generated by `_build/build.py`. Don't edit the generated `.html` files by hand; the next build overwrites them.

```bash
pip install pillow          # only needed to (re)generate images
python3 _build/build.py     # builds every page + sitemap.xml, robots.txt, .htaccess, 404.html
python3 -m http.server 5173 # preview at http://localhost:5173
```

| What to change | Where |
|---|---|
| Phone, email, address, review count, tracking IDs | constants at the top of `_build/build.py` |
| Services (trim, siding, decks, windows & doors, roofing, ADU) | `SERVICES` in `_build/build.py` |
| Town pages (`/service-areas/…`) | `_build/cities.py` |
| Blog posts (`/blog/…`) | one Markdown file per post in `_build/posts/` (front matter: title, seo_title, description, date, category, img, img_alt, service) |
| Homepage body | `_build/pages/home.html` |
| Photos | drop a JPG in `_build/img-src/` and reference it by name; the build makes WebP versions |
| Styles / scripts | `css/styles.css`, `js/main.js`, `js/tracking.js` (edit directly) |
| Redirects for old URLs | `REDIRECTS_301` / `GONE_410` in `_build/build.py` (written to `.htaccess`) |

## SEO built in

- One layout for every page: unique title (≤ 60 chars) and description, canonical, Open Graph/Twitter, `lang="en-US"`.
- JSON-LD: `HomeAndConstructionBusiness` with every town served, `Service` on service and town pages, `BreadcrumbList`, `FAQPage`.
- `sitemap.xml` (indexable pages only), `robots.txt`, real 404, `.htaccess` with redirects, www → bare domain, cache and security headers.
- Responsive WebP images (800w / 1600w) with real width/height; hero preloaded with `fetchpriority="high"`.

## Leads and tracking

- The estimate form posts to `/api/lead.php` on our own server (see **Spam protection** below), which forwards to the webhook. Each lead includes `lead_type`, `page_url`, `landing_page`, `referrer`, UTMs, `gclid` and `fbclid` (kept in localStorage for 90 days from the landing visit).
- After a successful send the visitor goes to `/thank-you/`.
- `js/tracking.js` loads GA4, Google Ads and the Meta Pixel **only** when IDs are set in `TRACKING` and only on the production hostnames. Events: `generate_lead` (+ Ads conversion and Pixel `Lead`), `phone_click`, `email_click`.

## Spam protection (form)

The form never talks to a third party directly. It posts to `api/lead.php` on Hostinger, which checks every request and only then forwards it. The webhook URL stays on the server, so bots can't find it in the page and post to it directly.

| Layer | What it stops |
|---|---|
| 4 honeypot fields (website, company, fax, "I am a robot"), hidden off-screen | Bots that fill every field |
| Signed token from the server, valid 4 s to 2 h, single use | Scripts that post without loading the page, instant submits, replays |
| Proof-of-work solved in the browser (a fraction of a second for a person) | Mass posting at scale |
| Rate limit per connection: 3 per hour, 6 per day | Floods |
| US phone validation (10 digits, valid area code) | Most foreign submissions (real people see an error and can fix it) |
| Content filters: non-Latin scripts, multiple links, SEO/crypto/marketing pitches, digits in the name | Spam pitches |
| Foreign signals: Cloudflare country (when present), browser time zone outside the Americas, browser language other than English/Portuguese/Spanish, ZIP outside MA, bot user agents | International bot traffic |
| Duplicate phone within 15 minutes | Double submits |
| `.htaccess`: only browsers may POST to `/api/`, WordPress probes get 410 | Scanners |

Bots that are caught get a fake "success" reply, so they don't learn what stopped them. Nothing real is lost: borderline cases are saved to `~/castro-data/quarantine.log`, every accepted lead to `leads.log`, and every rejection reason (no personal data) to `rejected.log`.

**Server config** (outside `public_html`), `~/castro-config.json`, permission 600:

```json
{
  "webhook": "https://your-webhook-url",
  "notify_email": "ecastrocarpentry@gmail.com",
  "email_copy": false
}
```

A random `secret` is added automatically on the first request. Leads are POSTed to `webhook` as JSON; if it's empty or fails, they're emailed to `notify_email`. Set `email_copy` to `true` to also get an email when the webhook works.

**Optional, strongest country filter:** put the domain behind Cloudflare (free plan). The script then reads the visitor's real country and drops non-US/CA submissions, and Cloudflare's WAF can challenge foreign traffic on `/api/` only. Leave "Block AI bots" **off** in Cloudflare so AI assistants can still read the site.

## Visible to AI assistants

- `robots.txt` explicitly allows Google, Bing, Apple, DuckDuckGo and the AI crawlers (OpenAI GPTBot/OAI-SearchBot/ChatGPT-User, Anthropic ClaudeBot/Claude-SearchBot/Claude-User, PerplexityBot, Google-Extended, Applebot-Extended, Amazonbot, Meta, Mistral, Common Crawl). Only `/api/` and `/thank-you/` are off-limits.
- `llms.txt` (generated) summarizes the business, services, towns and guides with links, for language models.
- Every page has the full text in the HTML (no JavaScript needed) plus structured data (business, services, FAQ, articles).
- In hPanel, keep any "bot protection" or challenge page **off** for normal pages, or AI crawlers and Google get blocked.

## Instagram feed (automatic)

The homepage has an "On Instagram" section that stays hidden until a feed exists. It is filled by `_build/instagram-sync.php`, run on Hostinger by a cron job. No third-party widget, and the token never reaches the browser.

1. The Instagram account must be **Business or Creator**.
2. In [Meta for Developers](https://developers.facebook.com/), create an app with the **Instagram API with Instagram Login** product, add the account as a tester, and generate a **long-lived access token**.
3. On Hostinger (SSH or File Manager), create `~/instagram-config.json` **outside** `public_html` with `{"token": "PASTE_TOKEN"}` and set its permission to 600.
4. hPanel > Advanced > **Cron Jobs**, every hour:
   `php /home/USER/domains/castrocarpentryinc.com/public_html/_build/instagram-sync.php`
   (use the real path shown in hPanel).
5. The script saves the latest 8 posts to `/instagram/` (git-ignored), writes `/instagram/feed.json`, and refreshes the token weekly so it never expires.

Without a token, nothing breaks: the section simply stays hidden.

## Deploy (Hostinger)

1. hPanel → Websites → castrocarpentryinc.com → **Advanced → Git**: connect this repository, branch `main`, install path `public_html` (empty the folder first: back up the WordPress files and database).
2. Turn on auto-deploy (webhook) so every push updates the site.
3. hPanel → Security: keep **Force HTTPS** on, and switch off any bot-protection/"anti-robot" challenge for normal visitors so Googlebot can crawl.
4. After going live: test old URLs (`curl -sI https://castrocarpentryinc.com/home/` → 301), submit `sitemap.xml` in Search Console, and remove the old `sitemap_index.xml`.
